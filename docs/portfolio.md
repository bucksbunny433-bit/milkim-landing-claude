# Кейсы: как менять фотографии работ

Это самая частая правка на сайте и единственная, где легко молча сломать сборку.
Разметку при этом трогать не нужно **никогда** — только папку с фото и один файл данных.

---

## Что такое кейс

Один кейс — это одна карточка в блоке «Мои работы». На экране это **квадрат, целиком
заполненный фотографией**, плюс счётчик «01 / 11» над ним и стрелки поверх снимка.
Ни подписей, ни «до/после», ни описаний — так решил клиент.

Две группы, они же две вкладки:

| Группа | Папка | Вкладка на сайте |
|---|---|---|
| Брови | `src/assets/portfolio/brows/` | Брови |
| Перекрытие | `src/assets/portfolio/correction/` | Перекрытие |

Внутри — папка на кейс: `01`, `02`, `03`…

Данные всех кейсов лежат в одном файле: **`src/content/cases.json`**.

---

## Три вида карточки

`layout` в данных говорит, из чего собран квадрат.

### `collage` — один готовый коллаж
Студия сама склеила «до и после» в один кадр. **Обязательно квадратный (1:1)** — тогда
он показывается целиком, без единого обрезанного пикселя. Это целевой вид, к которому
идут все кейсы.

```json
{
  "id": "brows-08",
  "service": "brows",
  "serviceTitle": "Брови",
  "number": 8,
  "layout": "collage",
  "frames": [{ "file": "brows/08/collage.jpg", "w": 3782, "h": 3782 }]
}
```

### `pair` — два настоящих кадра рядом
Временный вариант для кейсов, на которые готового коллажа ещё нет. Две фотографии
встают в квадрат бок о бок. Каждая обрезается **только по бокам**, вся высота остаётся.
Обязателен `role` у каждого кадра.

```json
{
  "id": "brows-01",
  "service": "brows",
  "serviceTitle": "Брови",
  "number": 1,
  "layout": "pair",
  "frames": [
    { "file": "brows/01/before.jpg", "w": 768, "h": 1024, "role": "before" },
    { "file": "brows/01/healed.jpg", "w": 960, "h": 1280, "role": "after",
      "focus": "0% 50%" }
  ]
}
```

### `single` — один результат
Когда кадра «до» просто не существует. Так показаны брови 05 и 06.

```json
{
  "id": "brows-05",
  "service": "brows",
  "serviceTitle": "Брови",
  "number": 5,
  "layout": "single",
  "frames": [{ "file": "brows/05/healed.jpg", "w": 2172, "h": 2172 }]
}
```

---

## Поля

| Поле | Что это |
|---|---|
| `id` | уникальный, вида `brows-12` или `correction-09` |
| `service` | `brows` или `correction` — больше ничего |
| `serviceTitle` | `Брови` или `Перекрытие`, ровно так |
| `number` | номер работы, целое число |
| `layout` | `collage`, `pair` или `single` |
| `frames[].file` | путь от `src/assets/portfolio/`, например `brows/12/collage.jpg` |
| `frames[].w` / `h` | **настоящий размер файла в пикселях** |
| `frames[].role` | только у `pair`: `before` у первого кадра, `after` у второго |
| `frames[].focus` | необязательно. `object-position`, например `"0% 50%"` |

**`w` и `h` обязаны совпадать с файлом.** Если соврать — Astro отдаёт в браузер
неуменьшенный оригинал: однажды сборка выросла с 3,4 МБ до 53 МБ ровно по этой причине.
Не подбирайте их на глаз, см. проверку ниже.

**Порядок карточек на сайте** — это порядок записей в `cases.json` внутри своей группы,
а не `number`. Хотите передвинуть работу вперёд — передвиньте её объект в массиве.

## Заменить фотографию в существующем кейсе

1. Положить новый файл в папку этого кейса, например
   `src/assets/portfolio/brows/01/collage.jpg`.
2. В `cases.json` найти кейс по `id` и заменить блок `frames`. Если это готовый
   квадратный коллаж — поменять `layout` на `"collage"` и оставить один кадр, убрав
   `role` и `focus`.
3. Выполнить:

```bash
npm run cases -- --fix   # подставит настоящие w/h и всё проверит
npm run build
```

Старые файлы можно оставить в папке — они просто не попадут на сайт. Скрипт покажет их
отдельным списком.

---

## Добавить новую работу

1. Создать папку со следующим номером: `src/assets/portfolio/brows/12/`.
2. Положить туда фото. Имена файлов — только латиница, без пробелов и кириллицы.
3. Добавить объект в `cases.json` — в конец своей группы или туда, где он должен идти.
4. `npm run cases -- --fix`, затем `npm run build`.

Счётчик «01 / 12» и число рядом с названием вкладки пересчитаются сами.

---

## Удалить работу

Убрать её объект из `cases.json`. Файлы можно не трогать.

---

## Проверка

```bash
npm run cases
```

Скрипт печатает все кейсы и ловит:

- файл, которого нет на диске (иначе на сайте будет пустая карточка);
- `w`/`h`, не совпадающие с реальным файлом;
- неправильный `layout`, `service` или число кадров;
- `pair` без `role`;
- фотографии в папках, на которые не ссылается ни один кейс.

С флагом `--fix` он сам проставляет верные `w`/`h`.

---

## Чего делать нельзя

- **Не обрезать готовые коллажи** и не менять их пропорцию. Они ровно 1:1, и любой
  кроп режет по половинам сравнения — то есть по самому содержанию кадра.
- **Не впечатывать подписи в фотографии.** Текст в растре не масштабируется между
  карточкой на телефоне и на десктопе, недоступен для скринридера, и его нельзя
  поправить, не переэкспортировав файл. Часть кадров уже несёт подписи студии — это
  их материал, его не трогаем и не дублируем.
- **Никаких стоковых и сгенерированных лиц, бровей и «до/после».** Каждый кадр с
  результатом — настоящее фото студии с полученным согласием на публикацию. Это
  требование не стилистическое: это доверие к мастеру и юридический риск в рекламе
  косметологической процедуры.
- **Не возвращать анимации** появления карточек. Их убрали намеренно: девятнадцать
  карточек со scroll-анимациями подвешивали перелистывание на телефоне.
